# 架构重构需求文档

**日期：** 2026-06-13
**状态：** 已部分落地，保留为重构需求背景；当前实现以 `src/` layout 为准
**背景：** 当前系统仅支持截面多因子选股（Top-K 轮动），无法支持海龟交易法、金字塔加仓、PE 择时等完整交易策略。本次重构目标是在保留现有能力的前提下，扩展系统支持多种策略范式。

---

## 1. 问题陈述

### 1.1 现有系统局限

| 局限 | 描述 |
|------|------|
| 仅支持截面选股 | 每个调仓日对全市场打分选 Top-K，无法对单票进行逐日进出场判断 |
| 批处理架构 | 选股结果预计算为 CSV，引擎读取 CSV 模拟交易，无法响应实时信号 |
| 固定调仓日历 | 只支持 week/biweek 周期调仓，无法按条件触发调仓 |
| 无单票仓位状态 | 引擎不跟踪单票的入场价、加仓层数、浮动盈亏等状态 |
| 配置与代码分离 | 旧版 YAML 在 `config/` 下、策略代码在 `core/`/`modules/` 下；当前已迁到 `src/` layout |

### 1.2 希望支持的策略类型

- **金字塔加仓**：趋势确认后分批建仓，每次新高或突破固定幅度追加仓位，ATR 动态止损
- **海龟交易法**：20 日高点突破入场，10 日低点出场，ATR 仓位计算，多空信号管理
- **PE/基本面择时**：按 PE 分位数决定持仓比例，低估买入、高估减仓

## 2. 功能需求

### 2.1 策略框架

| 编号 | 需求 | 优先级 |
|------|------|--------|
| F-01 | 支持信号驱动策略（现有因子选股路径，保留不变） | P0 |
| F-02 | 支持规则驱动策略（逐日 `on_bar()` 事件循环） | P0 |
| F-03 | 规则驱动策略支持单票仓位状态跟踪（入场价、加仓层数、止损线） | P0 |
| F-04 | 金字塔加仓策略作为首个规则驱动策略实现 | P0 |
| F-05 | 策略参数通过 YAML 配置，策略逻辑通过 Python 子类实现 | P0 |
| F-06 | 策略 YAML 与策略代码存放在同一目录下 | P1 |
| F-07 | 海龟策略作为第二个规则驱动策略实现 | P1 |
| F-08 | PE 择时策略作为第三个规则驱动策略实现 | P2 |

### 2.2 数据层

| 编号 | 需求 | 优先级 |
|------|------|--------|
| D-01 | 数据访问通过统一接口封装，策略代码不直接依赖 qlib/parquet 实现细节 | P0 |
| D-02 | 接口支持按日期范围获取单票 OHLCV 数据 | P0 |
| D-03 | 接口支持获取因子数据（parquet 基本面 + qlib Alpha158） | P0 |
| D-04 | 接口支持获取股票池（universe 过滤结果） | P1 |

### 2.3 回测引擎

| 编号 | 需求 | 优先级 |
|------|------|--------|
| E-01 | 保留现有 `QlibBacktestEngine` 用于信号驱动策略，不破坏现有回测 | P0 |
| E-02 | 新建 `RuleBasedEngine` 用于规则驱动策略，支持逐日事件循环 | P0 |
| E-03 | 两个引擎共用交易工具层（涨跌停判断、交易成本计算） | P0 |
| E-04 | 两个引擎输出统一的 `BacktestResult` 格式，可接入 Leaderboard | P0 |
| E-05 | `RuleBasedEngine` 支持多票并行状态管理 | P0 |

### 2.4 策略组织

| 编号 | 需求 | 优先级 |
|------|------|--------|
| O-01 | 策略按类型分目录存放：`strategies/factor/`、`strategies/pyramid/`、`strategies/turtle/` | P1 |
| O-02 | 旧版模型和因子 YAML 迁移到 `src/strategy/configs/` 对应目录 | P2 |
| O-03 | `main.py` 按策略类型自动分派到对应引擎 | P1 |

## 3. 非功能需求

| 编号 | 需求 |
|------|------|
| N-01 | 现有 80+ 因子策略回测结果与重构前一致（数值不变） |
| N-02 | 新引擎支持与现有引擎相同的回测指标输出（年化、夏普、最大回撤） |
| N-03 | 新策略类型支持参数扫描（多个 YAML 对应同一策略类，只改参数） |
| N-04 | 代码变更不影响 `scripts/paper_trading.py` 的实盘模拟流程 |

## 4. 不在本次范围内

- 实盘交易对接（非回测）
- 多账户管理
- 期货/期权支持
- Web UI / 可视化看板

## 5. 成功标准

1. 金字塔加仓策略可以通过 `python main.py backtest -e rule -s src/strategy/producers/configs/pyramid_atr_3layer.yaml` 运行回测
2. 回测结果可以出现在 `python main.py leaderboard` 中与因子策略对比
3. 现有所有因子策略回测结果数值不变
4. 新增策略只需：新建策略目录 + 写 Python 子类 + 写 YAML 参数文件，无需修改引擎代码
